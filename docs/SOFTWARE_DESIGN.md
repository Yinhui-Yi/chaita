# ChaitaAssistant 软件设计

## 1. 需求

| | 内容 |
|---|---|
| **输入** | 捕获游戏窗口的画面 |
| **输出** | ① 人物当前状态（结构化数值）② 当前地图的原始截图 |
| **使用方式** | 悬浮层盖在游戏上面，点「读取」抓一次 |

**不做的事：** 网格定位、逐格识别、认怪物名字、算伤害、求路线。地图只要一张截图，不需要看懂它。

---

## 2. 支持的两座塔

| 塔 | 引擎 | 窗口进程 | 抓图尺寸 | 面板 / 地图 |
|---|---|---|---|---|
| 教程塔 | RMXP（RGSS Player） | `game.exe` | 969×764 | 左侧黑底状态栏 / 右侧 11×11 |
| 喵塔 | h5mota（浏览器） | `msedge.exe` | 2217×1362 | 左侧面板 / 右侧 11×11 |

**两塔的 UI 完全不同**：面板位置、字段数量、钥匙表示法都不一样（教程塔有魔防/经验/金币和四色钥匙，喵塔只有生命/攻击/防御和三色钥匙）。所以**每塔一份描述**，不做通用识别。

---

## 3. 架构

```
UI 层（悬浮层）      PySide6 + QML，透明置顶
   │ 点「读取」       后台线程，避免冻住界面
   ▼
抓图                PrintWindow + PW_RENDERFULLCONTENT（chaita/game/capture.py）
   │ 整窗一张          被遮挡也能抓，且**先抓图再 import 读图逻辑**（省 ~2 s 启动）
   ▼
判画面类型          视觉模型看一眼：地图 / 怪物手册
   │
   ├── 怪物手册 ──→ agent.monster.read   一个会话：look 放大 + sprite 抠图标
   └── 地图    ──→ agent.map.read        一个会话问三句：层号 / 这层怪 / 这层资源
                    agent.map.monsters   「↻」只问这一层的怪
   ▼
显示                 状态数值 + 本层怪（数量/技能）+ 资源 + 地图截图

对话                agent.chat.reply  玩家说一句话：聊天 / 问事 / 顺手纠正读错的字段
                    （多轮：最近 8 轮对话随请求带上；截图每句都发一次）
```

**三条硬规矩（都是 owner 定的）**：

1. 工具只给**信息**，不算结论：不计算伤害、不判断能不能打，决策留给玩家。
2. 读图只由 AI 做：代码不写颜色判断/模板匹配（裁剪与 rembg 抠图除外）。
3. 一次读取**一张图只上传一次**：所有问题在同一个会话里追问，后续只发文字。

## 5. 抓图

**用 `PrintWindow` + `PW_RENDERFULLCONTENT`，不用抓屏幕。**

| | 抓屏幕（dxcam） | `PrintWindow` |
|---|---|---|
| 窗口被遮挡 | ❌ 抓到盖在上面的东西 | ✅ 窗口自己渲染一份 |
| 坐标 | 屏幕物理像素 | 逻辑像素（本机 150% 缩放下更小） |
| 适用 | 需要与屏幕像素对齐（画叠加层） | 只要一张给人/给模型看的图 |

本项目只需要"看见"，所以选 `PrintWindow`。实测两个窗口在**被别的窗口盖住时照样抓得到**。

**必须 `SetProcessDPIAware()`**，否则 Windows 按 150% 虚拟化坐标骗你：教程塔真实矩形 `(693,215) 969×764` 会被报成 `(462,143) 646×509`。

## 6. 切区域

### 6.1 按参考尺寸归一化

`PrintWindow` 的输出尺寸**随窗口大小变化**（同一个 Edge 窗口 1524 宽和 2217 宽抓出来的图不一样）。所以：

1. 抓到的图先缩放到塔描述里的 `ref_size`
2. 用参考尺寸下量好的绝对矩形去裁

这样区域坐标只量一次，窗口缩放后仍然有效。

### 6.2 实测区域

| 塔 | 参考尺寸 | 面板 | 地图 |
|---|---|---|---|
| 教程塔 | 969×764 | `(0, 28, 163, 478)` | `(163, 28, 483, 478)` |
| 喵塔 | 2217×1362 | `(400, 195, 350, 1150)` | `(735, 186, 1092, 1092)` |

喵塔地图区的量法：列亮度 > 60 的连续区间是 `x=735..1826`、`y=186..1277`，宽高都是 **1092**（正方形，与 11×11 吻合）。

### 6.3 裁掉边缘黑边

区域坐标按参考尺寸量，窗口尺寸一变就可能多带进一点画布外的黑底。`trim_black()` 把"整行/整列全黑"的边缘去掉，每边最多裁一半，避免误伤内容。

## 7. 读人物状态

### 7.1 用视觉模型，但必须给字段清单

模型：`deepseek-v4-flash-vision-exp`（一张图计 384 tokens，价格与 V4-Flash 相同）。

**必须把该塔的字段清单写进提示词，并明确"没出现的一律输出 null"。**

实测对比：

| 做法 | 喵塔的结果 |
|---|---|
| 不给清单 | 返回了 `level`/`mdef`/`exp`/`gold` —— **面板里根本没有这几项，是编的** |
| 给清单 | `{"floor":1,"hp":300,"atk":15,"def":5,"keys":{...}}` ✅ 正确 |

### 7.2 字段清单

| 塔 | 字段 |
|---|---|
| 教程塔 | floor / level / hp / atk / def / mdef / exp / gold / keys(黄蓝红绿) |
| 喵塔 | floor / hp / atk / def / keys(黄蓝红) |

### 7.3 输出

```json
{"floor": 0, "level": 1, "hp": 2, "atk": 1, "def": 0,
 "mdef": 0, "exp": 0, "gold": 0,
 "keys": {"yellow": 0, "blue": 0, "red": 0, "green": 0}}
```

`parse_status()` 容错处理模型偶尔裹上的 markdown 代码块。

## 8. 只读前台的游戏

**规则只有一条：只读用户刚才在看的那个窗口里的游戏。**

点「读取」那一刻，前台是**悬浮层自己**（`pythonw.exe`），不是游戏。所以用 120ms 轮询，记录"最后一个非悬浮层的前台进程"，点读取时拿它去匹配塔的进程名。

- 匹配上 → 读那座塔
- 匹配不上 → **明确拒绝**并说明前台是什么，不做任何猜测

**删掉了"按顺序挨个试"的逻辑。** 两座塔都开着时先命中的那个会永远赢 —— 实测用户看着 A 点读取却总读到 B，表现就是"点了没用"。

## 9. 画面校验

浏览器窗口里可能是任意页面（实测抓到过文档站）。所以读之前先校验：

| 判据 | 阈值 |
|---|---|
| 地图区平均亮度 | 教程塔 0~200、喵塔 20~210（文档页白底约 252，会被拒绝） |
| 地图区灰度标准差 | ≥ 8（纯色页拒绝） |

不通过就报「画面看起来不是游戏」，而不是白烧一次模型调用。

## 11. 踩过的坑（都是实测）

这些不写在代码注释里会重犯：

| 坑 | 现象 | 解法 |
|---|---|---|
| DPI 虚拟化 | 窗口坐标比实际小 1.5 倍，抓歪 | `SetProcessDPIAware()` |
| Edge 标题含零宽字符 U+200B | 按标题前缀匹配莫名失败 | 改按**进程名**匹配 |
| `PrintWindow` 与屏幕坐标系不同 | 960×720 客户区抓出 646×506 | 输出只给人看，不与屏幕像素对齐 |
| `PrintWindow` 输出尺寸随窗口变 | 窗口缩小后区域全歪 | 归一化到参考尺寸 |
| 窗口级 `installEventFilter` 收不到 `NativeEvent` | `WM_NCHITTEST` 一次没进来 | 装在 `QGuiApplication` 上，用 `QAbstractNativeEventFilter` |
| 顶栏报 `HTCAPTION` | Windows 接管鼠标，按钮和折叠同时失效 | 顶栏不报 `HTCAPTION` |
| QML 兄弟节点顺序 | 拖动 `MouseArea` 声明在后面，把按钮点击吃掉 | 拖动 `MouseArea` 必须声明在按钮**之前** |
| QML 无法动画 `QQuickWindow` 几何 | `Behavior`/`NumberAnimation` 在 `height` 上直接跳变 | 用 Python `QTimer` 逐帧插值 |
| 对绑定的 `width`/`height` 直接赋值 | 设 520 只得 373（按比例折算） | 不用绑定，用命令式赋值 |
| `Image.source` 不认 `QImage` | `Unable to assign QImage to QUrl` | 落盘传 `file://` 路径 |
| **QML 按 URL 缓存图片** | 读了教程塔却显示喵塔的地图 | 每次读取用不同文件名 |
| 模型会编字段 | 面板没有的字段也返回 | 提示词给字段清单 +「没出现的一律 null」 |
| 思考 token 吃光预算 | `max_tokens` 小时正文空（finish=length，预算全烧在推理） | 预算提到 12000，并且**直接关掉 thinking**（`extra_body={"thinking": {"type": "disabled"}}`）：58~135 秒 → 1~3 秒 |
| 模型给不了精确坐标 | 说地图在 `(425,90)`，实际 `(340,88)`；数格子直接失败 | 几何靠代码量，模型只读文字面板 |
| 会话每次 `asyncio.run()` 开新循环 | 同一会话问第二句必崩 `ChatClientException: Event loop is closed`（httpx 连接池挂在第一个循环上） | 循环跟着会话走：`asyncio.new_event_loop()` + 每句 `run_until_complete`，用完 `close()`；探针 `tools/check_session_loop.py` |
| `try/except: pass` 里的代码写错了 | 不报错、只是**永远不执行**：拆目录时漏导入 `_LOGS`/`qVersion`，崩溃日志和 `app.start` 静默失效（crash.log 永远 0 字节，看着像从没崩过） | 被 `try/except: pass` 包住的代码必须有测试证明它真做了事（`tests/test_startup.py`）；真机验收看日志里有没有 `app.start` |
| 手写的「QML 用到的签名」清单 | 漂了：列着 7 个 QML 早就不调的槽 | 用自动扫描（`test_every_qml_call_is_a_slot` 直接扫 QML 正文）当防线，手写清单只留当下确实在用的 |

## 12. 关键验证结论（2026-10-26 重测）

| 能力 | 表现 | 证据 |
|---|---|---|
| 看懂是什么游戏 / 有什么面板 | ✅ | 早期实测（第 7 节） |
| 读带文字标签的面板 | ✅ 逐项全对 | `tools/_update_live.py`：floor「通天塔 1 层」hp 300 atk 15 def 5 |
| 读缺项/图形化的面板 | ⚠️ 不给字段清单就会编数据 | 第 7 节那张对比表 |
| 一次模型往返（关思考） | **1.7 ~ 2.3 秒** | `tools/check_session_loop.py`、`tools/_time_manual.py` 的日志行 |
| 同一会话连问三句 | ✅ 不会 `Event loop is closed` | `tools/check_session_loop.py` |
| 读怪物手册（2582×1390，5 只怪） | **21.5 ~ 55.6 秒**，字段 20/20 对，图标 5/5 | `tools/_time_manual.py` |
| 读地图（层号 + 怪 + 资源，一个会话） | **32.5 ~ 79.8 秒**（差异在 `look` 次数） | `tools/compare_look_map.py` |
| 对话（多轮：聊天 + 纠错 + 追问） | **1.4 ~ 2.9 秒 / 句** | `tools/check_chat.py`（三轮真实往返） |
| 同一张地图读两遍名字是否一致 | 加候选名后 ✅ 8/8 一致；不加 ❌ 4/12 | `tools/compare_map_stability.py` |
| 给精确像素坐标 / 数格子 | ❌ | 早期实测（几何一直由代码量） |

**结论没变：语义交给模型，几何交给代码；耗时的变量是"模型这一轮调了几次 look"，
不是模型本身。**

## 13. 已知限制（2026-10-26）

| 项 | 说明 | 严重度 |
|---|---|---|
| `look` 次数只有**兜底上限**（6 次）、每只怪 sprite 最多 3 次 | 正常读用不到（实测 ≤3 次），只拦病态循环：同一张缩略图以前 17 次 look 不收敛、7 分钟不返回，现在 67 秒出 6 行 | 低（要不要更严是质量取舍，等 owner） |
| 抠图要 u2net 模型 | 本机 `~/.u2net` 没有模型文件，`sprite` 退回**纯裁剪**（图标带底纹）；模型放进去就恢复干净抠图，代码不用改。另：素材库图标按名字命中率很低（实测 5 只怪只中 1 只，且 26×25 比 AI 裁的 157×146 小很多），所以不打算拿库里的顶替 | 中（想要干净图标就放模型） |
| 浏览器多标签 | 抓的是窗口当前显示的标签，无法指定具体标签页 | 低 |
| 自动持续读取 | 未做，现在点一次读一次 | 低（按设计） |
| 单实例保护 | ✅ 已做：`logs/app.lock`（`QLockFile`），第二次启动直接退出、不建窗口；死进程留下的锁会被下一次启动接管 | — |
| `config.yaml` 明文存 key | 已加进 `.gitignore`，仍建议用环境变量 | 低 |
| 画面校验是启发式 | 暗色主题网页可能骗过亮度判据 | 低 |
| 地图上的怪名受候选名影响 | 读地图会把面板里已有怪名当候选（换来 8/8 的一致性），若面板里有错名，错误会被沿用 | 低（错名来自手册，可手改） |
