# 魔塔是什么 · 玩家到底需要什么（ChaitaAssistant 产品依据）

> 写这份的原因：用户要"**详细学习魔塔的方方面面，充分理解玩家的核心需求，必要时自己游玩**"。
> 这份文档是**结论 + 证据**：结论能用在这几件事上（界面该显示什么、哪些能自动算、哪些必须问用户），
> 证据都在最后一节，能复现。
> 别把它当百科抄本 —— 每一条都标注了"从哪来"（塔的代码 / 实机引擎 / 老攻略记录）。

---

## 0. 一句话

魔塔（Magic Tower）是**回合制的最优化问题**：你的每一个动作都在花血、花钥匙、花回合，
玩家要的不是"过关"，是**在血够用的前提下把属性（攻/防/魔防）拿全，再打 boss**。
所以玩家反复算的东西只有三类：**打这只怪掉多少血**、**这颗宝石值不值得绕路**、**钥匙还够不够**。

---

## 1. 核心循环

```
看见门/怪/道具 → 判断值不值得动 → 动（掉血 / 用钥匙 / 拿道具 / 属性+） → 血量上限每层刷新 → 下一层
```

- **属性只增不减**（红/蓝/绿宝石、剑、盾），**血是消耗品**（每层入口按你的血量上限补满，很多塔是"回到满血"或"按比例"）。
- **钥匙是路费**：黄 → 蓝 → 红，逐级门；钥匙不够就只能绕，绕就是多掉血。
- **怪物是收费站**：打得过也要算"划不划算"，很多怪的正确打法是**不打**（绕过去），或者**等属性更高再回来打**。
- **boss 是终局条件**：多数塔只有一个真正的胜利条件（杀掉某只 boss），其余都是"攒属性/攒血"的过程。

## 2. 战斗数学（这一节决定了界面该不该替你算）

### 2.1 通用公式（经典魔塔）

```
per      = hero_atk - mon_def            // ≤ 0 ⇒ 根本打不动（伤害为 null / 无法开战）
turn     = ceil(mon_hp / per)            // 需要几回合
per_dmg  = max(mon_atk - hero_def, 0)    // 每回合掉多少血（我防高就 0）
damage   = (turn - 1) * per_dmg - hero_mdef
```

`turn - 1` 是因为**最后一回合怪已经死了、不再还手**；`mdef`（魔防）在整场里只抵一次。

### 2.2 但公式**不是全局常量**：每座塔都能自定义

h5mota 的约定是 `project/functions.js` 里的 `getDamageInfo` 由塔作者实现，同一个引擎能跑出完全不同的战斗模型：

| 塔 | 战斗模型 | 位置 |
|---|---|---|
| MT1005（国庆小塔） | 上面那条公式 | `mt1005-solve/mt1005/project/functions.js` |
| xinxin 包 | 一个几百行的 `MagicTowerSimulator` 类（闪避 `eva`、暴击 `crit`、连击次数 `k_value`、boss1/2/3 型、魔法、坚固、先攻…） | `xinxin/mota_pack_*/project/functions.js` |
| xinxin2 包 | 回合制模拟器：气/魔力（`ki`/`mana`）、技能条、中毒、吸血比例、石头怪特判… | `xinxin2new/xinxin2/project/functions.js` |

**产品结论**：ChaitaAssistant 不能硬编码一套公式去"帮玩家算伤害"，
但可以**用经典公式给一个估算**（显示"约掉 336 血 / 7 回合"），并且把"这是估算"说清楚 ——
这正好对上用户之前反复提的"技能数值同名不同层不一样""效果别让我填"之类的抱怨：
**数字是塔给的，不是我们编的**。

### 2.3 实机验证（不是抄公式，是问引擎）

用本地引擎（MT1005）在开局状态 `hp888 atk10 def10 mdef0` 下，让它自己算本层 13 只怪的伤害：

```
水银战士   hp48  atk66  def3   dmg336   turn7     ← 无特殊技能
  手算：per = 10-3 = 7；turn = ceil(48/7) = 7；dmg = (7-1)*(66-10) = 336 ✓
高级巫师   hp15  atk19  def9   dmg126   turn15    ← 坚固(3)：防御被改成"我方 atk−1" ⇒ 回合数恒 15
  手算：per = 10-9 = 1；turn = 15；dmg = (15-1)*(19-10) = 126 ✓
金骑士     hp128 atk44  def22  dmg=null           ← def ≥ 我方 atk ⇒ 打不动
剑圣       hp78  atk26  def6   dmg608   turn20    ← 连击(4)+仇恨(17)：比同数值的怪贵得多
```

完整输出见 `tools/research/floor_damage.js`（脚本直接用塔的 `core.enemys.getDamage`，不是我自己实现公式）。

### 2.4 临界值（高级玩家的核心概念）

- **临界值**：让 `turn` 少 1 回合所需的最小攻击力。到点就"质变"，差 1 点攻击可能差一整回合的伤害。
- **临界减伤**：加防御到某条线，可以少挨一整回合。
- 极端例子（MT1005 终局）：`damage = 3019 × (31 − def) − mdef`，
  **def 从 29 补到 30，整场少掉 3019 血**；攻击差 1 点则是"根本开不了战"。
  → 玩家对"我现在离临界值还差多少"极度敏感。

## 3. 特殊技能：玩家眼里它们不是名字，是"会不会翻车"

78 个技能名已经进库（`assets/monster_templates.db` 的 `skill` 表）。按**战术含义**分组：

| 组 | 技能 | 玩家真正在意的事 |
|---|---|---|
| 出手顺序 | 先攻 / 先攻改 | 先攻 = 怪物多打一下 ⇒ 伤害 +1 回合；血不够会**被反杀** |
| 多段/免伤 | 2连击 / 3连击 / 二回攻击 / 三回攻击 / 模仿 | 伤害 ×段数；模仿 = 按你上次的伤害来 |
| 破防 | 破甲 / 破防 / 无视防御力 / 变硬 / 硬化 / 坚固 | 直接改公式里的一侧（防御被打掉 / 防御变我方 atk−1 ⇒ 回合数恒定） |
| 回复/吸血 | 吸血 / 吸血攻击 / 再生能力 / 不死 | 打它=白打，必须先一口气打穿或者绕开 |
| 持续伤害 | 中毒 / 衰弱 / 诅咒 / 毒攻击 / 衰弱攻击 / 猛毒 | 战后还在掉血，玩家要预留血量 |
| 邻格惩罚 | 领域 / 阻击 / 光环 / 支援 / 夹击 | **不打架也掉血**：路线要绕开它的十字/九宫 |
| 强制战斗 | 自爆 / 捕捉 / 特殊战斗 | 踩上去就被拖进战斗，且常伴随"战后 hp=1" ⇒ 只能最后打 |
| 越拖越贵 | 仇恨 | 每次击杀都让它更疼，**早打便宜、晚打很贵** |
| 地形联动 | 冰面 / 灯 / 熔岩 / 血网 | 滑行、一次性通道、每步掉血 —— 路线设计的一部分 |
| boss 型 | BOSS Ⅰ/Ⅱ/Ⅲ型、剑大师 / 盾大师 / 超负荷魔力 | 免疫某些手段（反弹/破防/魔法），只能用数值硬碰 |

**产品结论**：技能应该**一眼看出"要不要绕"**。现在界面只是把名字列出来，
缺的是"这只怪属于哪一类（先攻/自爆/领域…）+ 玩法提示"。

## 4. 资源与钥匙经济

- **属性道具必须全取**：红宝石=攻、蓝宝石=防、绿宝石=敏/魔防、剑盾=攻防；漏一件可能就是"打不动 boss"。
- **血瓶是"续航"**：该吃就吃，不必省（MT1005 的搜索结论：属性道具全取 ⇒ 实际收敛到"全取 + 非 boss 掉血最小"）。
- **效果来自塔的数据**：`items.js` 的 `itemEffectTip` + `data.js` 的 `values`
  → 已抽成 `assets/item_effects.json`（红宝石 攻击力 +2、红血瓶 体力 +150 …），**不该让玩家手填**。
- **钥匙是硬通货**：黄钥匙数以十计、蓝/红以个计；"这把黄钥匙能省多少血"是常见决策。

## 5. 地图与路线

- **一格踩一次**：绕路 = 多掉血，所以"能不能少走一步"是真的有意义（MT1005 的搜索口径甚至记录"一格被踩超过 5 次就丢弃这条分支"）。
- **轻按（空格/SP）可以拿身边的东西而不移动** —— 实测能省掉踩上去的代价：

  | 操作 | 结果 | 代价 |
  |---|---|---|
  | `R SP`（走到旁边，轻按拿红宝石） | hp 888 → 868，atk 10 → 11 | **−20** |
  | `R R`（直接走上去捡） | hp 888 → 868 → 843，atk 10 → 11 | **−45** |

  同一次拾取差 25 血；一条 100 键的路线里这种差价会累积成"能不能打 boss"。
  （这条是**我在本地引擎里亲自跑出来的**，见 §8。）
- **"下一个资源"**：从当前位置出发、**不经过其它资源**就能拿到的资源 —— 规划路线时的原子单位。
- 常见地形：冰面（踩上就滑，撞墙才停）、一次性灯/暗路、熔岩/血网（每步掉血）、暗墙、传送、商店。

## 6. 玩家的核心需求（按我理解的优先级）

1. **这只怪我现在打要掉多少血 / 会不会打不动**（伤害 + 回合 + 能不能打）。
2. **本层还有哪些怪没打、哪些资源没拿**（清单，别重复跑）。
3. **我离临界值还差多少**（攻/防差几点 = 少几回合）。
4. **钥匙够不够、这扇门开了值不值**。
5. **打谁先、打谁后**（仇恨怪要早打；自爆/捕捉怪要最后打；领域怪要绕）。
6. **别让我重复输入已知信息**（道具效果、怪物属性、技能含义 —— 都在塔的数据里，查得到）。
7. **记录要可信**：血/攻/防/钥匙必须和画面一致，错一个数整盘规划就废了。

## 6.5 实战场景（把上面的结论串起来）

玩家在一层的真实决策链（我按引擎数据复现过其中前两步）：

1. 读画面 → 记下 `hp888 atk10 def10 mdef0`、四色钥匙、本层怪/资源。
2. 问：**哪些怪现在打要掉多少血**（§2.3 那张表）→ 掉血少的先打，`dmg=null` 的（金骑士）记着"打不动"。
3. 问：**这颗宝石值不值得绕**（§5 的 `R SP` vs `R R`：差 25 血）。
4. 问：**现在够不够打 boss**（§2.4 的临界值：至少 atk 31、def 30，血 > 2995）。
5. 打完一层 → 属性只增不减，下一层重来。

**注意第 2 步里"打不动"和"掉 608 血"是两类完全不同的结论**：
一个意味着"这条路现在过不去"，另一个意味着"可以过但很贵"。界面必须能区分。

## 7. 对 ChaitaAssistant 的启示

### 已经有了
- 读画面记：属性/四色钥匙/破炸飞/金币经验、本层怪与资源、怪物手册（技能 + 数值）、地图截图。
- 本层编辑（点数量只改数量）、技能一行一个且能填数值、资源效果自动带出、模板库按图去重 + 强弱/家族排序。

### 明显缺口（按"离玩家需求最近"排序）
1. **不替你算"打这只怪掉多少血"**：已有 hero 的 atk/def/mdef 和每只怪的 hp/atk/def，
   只差一次乘法 —— 用 §2.1 的经典公式给**估算**，并标注"按经典公式估算，塔可能自定义"。
2. **没有"还差多少"**：`临界值` 提示（"攻 +3 可少 1 回合"，"防 +2 可少挨 336 血"）。
3. **技能没有"要不要绕"的提示**：把 §3 的分组做成标签/提示（先攻、自爆、领域…），红色标危险。
4. **没有本层待办清单**：哪些怪打过/没打过、哪些资源拿了没拿。
5. **读错无法纠**：底部纠错区一直没在真模型上验证过（旧账）。

### 不建议做
- 不要自己写战斗引擎去替代塔的实现（每塔公式不同，写一套必错；xinxin 是几百行模拟器）。
- 不要自动规划完整路线（MT1005 的搜索是 5 万行脚本 + 引擎重放才敢下结论；而且用户明确说过"路线我来定"）。
